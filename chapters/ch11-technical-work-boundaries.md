# 第11节：程序员和技术人容易踩的红线

来源：用户提供PDF第389–412页，共17条。页码为PDF物理页，第一页计1。下面的方法与示例为转换整理；下方表保留书中标题和等级作定位。

## 核心判断
技术接单先检查书面授权、数据来源、资金用途和知识产权，再决定实现范围。

## 使用方法
1. 把接单用途、系统所有者授权和数据来源问清，发现赌博诈骗或未授权访问时停止相关工作。（11.4–11.5、11.8–11.10）
2. 离职交接列账号、权限、代码和资料，不拿删库、后门或客户数据处理工资纠纷。（11.6–11.7）
3. 产品检查许可证、隐私、日志和上线业务；开源项目与公司资源分开记录。（11.12–11.17）

使用时先选与问题相符的条目，再核对适用条件，分别填成本、收益口径与证据。书中标题不能替代完整条目，也不能独立作为当前法律或医学指令。详细数字不在此表内；需要时用条目页码回读原PDF，并核对原始研究或官方当前资料。

## 关键概念
- 书面授权
- 数据最小化
- 职务成果
- 开源许可证
- 业务用途

## 应用示例
接一个采集网站数据的需求：先确认网页公开性、访问限制、信息类别、使用及转售目的和书面授权，核对当前规则，再决定哪些数据可处理。授权不清先缩小范围。

## 容易出错的地方
- 忽略个人条件，直接照标题行动。
- 把书中证据等级与作者性价比判断合并成一个分数。
- 第11.1条的追究能力分析是作者风险判断，不能作为允许违规的条件；公开可见也不自动意味着可采集、可售卖。

## 可执行收获
1. 把本节问题转成具体行为或办理路线。
2. 把有条件、需核验、已有证据支持的内容分开写。
3. 只挑一两条现在可做的动作，给出触发条件或核验步骤。
